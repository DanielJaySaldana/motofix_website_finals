# MotoFix presentation and debugging guide

## What was copied

The public website at https://watch-actor-53112760.figma.site/ supplies the page
markup, compiled CSS, client-side JavaScript, images, fonts, video, and interactive
MotoFix 5.2 prototype used in this project. The original unpublished TSX source
and original Figma Make document are **not** accessible through the published URL.
The system JavaScript retained here is formatted published code, not recovered
original component source. The promotional page has been separated into editable
HTML and CSS with a readable progressive-enhancement JavaScript controller.

| Contact and feedback | `promotional/contact.html`           | `src/promotional/contact.css`           |
| Shared navigation    | `promotional/header.html`            | `src/promotional/header.css`            |
| Shared footer        | `promotional/footer.html`            | `src/promotional/footer.css`            |

Each section stylesheet keeps its base styles and any section-specific responsive
and motion rules together. Shared utility classes still come from `src/shared/base.css`
and Tailwind's `src/index.css`; common promotional components live in `shared.css`.
For example, a section using `promo-container` inherits that shared container style.

These HTML files are **partials of one scrolling page**, not separate navigation
destinations. `index.html` uses `<!-- include: "home.html" -->` directives. The
Vite plugin expands them before the page is served or built; browsers do not
natively process include comments. The same assembler processes the React preview's
raw HTML import, so editing a section changes both versions.

Our Prototype is included inside `about-us.html` to retain its existing visual
layout and shared About Us container. Its actual markup is only in
`our-prototype.html`. Contact includes the existing feedback form and the contact
call-to-action, without merging or changing their original section IDs.

## Explaining HTML versus CSS versus behavior

1. Open `promotional/index.html` to show the page shell and section order. Then
   open the section's own HTML file to explain its headings, links, images, form
   labels, or tab panels. No actual-system application markup is embedded here.
2. Open `src/promotional/promotional.css` to show the stylesheet imports, then
   the matching section CSS file to explain its layout, effects, and breakpoints.
   Use `shared.css` for reusable promotional components; do not confuse the
   shared utility sheet with the actual system stylesheet.
3. Open `src/promotional/promotion.js` to explain dynamic behavior. HTML and CSS
   alone cannot play the video on demand, switch audiences, or manage tabs.
4. Follow `/preview` to the separate system entry. System screens are generated
   from React client code, so a shell HTML document cannot contain every possible
   state as hand-written static HTML.
5. The primary Make preview uses `src/App.tsx` to select the appropriate application.
   Exported sites use separate entry files and the provided Python route handler.

## Important functional boundaries

- In XAMPP, account credentials, sessions, role-specific records, support tickets,
  and uploaded files use the local MySQL database. The original Python static preview
  remains browser-only. Built-in demo accounts are available below the login form.
- Payments and third-party integrations remain simulations. No payment is collected,
  and Google sign-in/email delivery require online service credentials.
- The original published feedback form uses a private Next.js server action that
  cannot be exported. The XAMPP version saves feedback to the local
  `motofix_promotional.feedback_submissions` table and does not contact the
  original site.
- Native `.make` exports must be produced through Figma Make itself:
  **Main menu → File → Save local copy**. A published website cannot trigger this
  proprietary export. No ZIP has been renamed to `.make`.
- A public URL does not provide the original editable Figma document or its
  complete original development history.

## Running downloaded packages

For the XAMPP version, start Apache and MySQL, import `database/motofix.sql`
through phpMyAdmin, and open `http://localhost/motofix_website_finals/`. The
promotional feedback and interactive demo records are stored in the local database.

For the original static presentation, install Python 3 and run `python serve.py`
(`python3 serve.py` on some systems). Open `http://localhost:8080`. This original
static preview does not use the XAMPP database. Do not open HTML via `file://`:
ES modules and root-relative assets require an HTTP origin.

For source development: from `source/`, install dependencies with `pnpm install`
and build with `pnpm build`. The included website is already built, so Python
is enough to present it.

The promotional-only package contains no system JavaScript, system stylesheet,
or system HTML. Its three demo buttons open the original published prototype and
therefore require an internet connection. Promotional screenshot images remain,
because those are visible content of the promotional page itself.

## Rebuilding the download packages in the main project

Run `pnpm export:packages` and then `pnpm verify:archives`. These use the separated
HTML entry points and include every section HTML/CSS source file and the HTML
assembler in both ZIPs. Archive checks verify ZIP integrity, assembled section
IDs, source separation, required local assets, and the exclusion of actual-system
files from the promotional-only archive.

Run `pnpm test:promotional` to check template composition, nested dependencies,
section stylesheet imports, and clear failures for missing or invalid includes.
